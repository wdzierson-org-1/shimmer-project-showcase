# Agent-readable portfolio preview

Local preview: `npm run build && npm run preview`, then http://localhost:4173. To see what AI agents receive, run `npm run check:agents` while the preview is up.

Every public URL now returns its content in the HTML the server sends, so AI agents, crawlers, and link unfurlers no longer see an empty page. After `vite build`, a build plugin (`scripts/agent-pages`) reads the same Supabase rows the site reads in the browser and writes into `dist/`: one page per view with its content rendered inside `#root` (hidden from JavaScript visitors by a class set in the page head, then replaced by React when the app mounts), per-page titles, descriptions, canonical URLs, Open Graph and Twitter tags, and schema.org JSON-LD (Person, ProfilePage, CreativeWork, Article); a Markdown copy of each page; `llms.txt` and `llms-full.txt`; and `sitemap.xml`, which `robots.txt` now names. Before this change every URL returned 0 words of readable text. Against the live CMS on 2026-10-22 the local build returns 1,787 words on the homepage, 348 on the career page, 397–585 on a case study, and 1,441 on an essay; `llms-full.txt` holds 14,417 words and the sitemap lists 32 pages.

Case studies, essays, and the career page have real paths: `/project/<id>`, `/essay/<id>`, and `/career`. Links shared before this change (`/#case=…`, `/#essay=…`, `/#career`) still open the same view and switch the address bar to the path, so copied links work for agents. Ask AI citations, the dashboard's share link, and the logo wall use the paths, and the tab title follows the view.

The CMS and admin panel are unchanged. The browser site still reads Supabase live, so edits appear for visitors immediately. The agent copy is written when the site is built, so it refreshes on each `vercel --prod`. A project added since the last deploy still opens normally in the browser; agents get the homepage for it until the next deploy. Unlisted projects keep a working direct page marked `noindex` and stay out of the homepage copy, `llms.txt`, `llms-full.txt`, and the sitemap. The build fails rather than publishing empty pages if Supabase can't be read, no listed projects come back, or `index.html` loses its `<!-- page-meta -->` block.

**After hiding or unlisting a case in the admin panel, run `vercel --prod`.** The browser site drops it at once, but until the next deploy its agent page stays online and indexable, and it stays in the sitemap, `llms.txt`, `llms-full.txt`, and the homepage copy. Editing a case's text has the same delay, with lower stakes. Removing the delay needs new infrastructure: a deploy trigger needs Git integration or a stored Vercel token, and request-time rendering needs a server function.

Copy the site and the agent pages share now lives in `src/concepts/practice/profile.ts` (hero, practice lenses, career roles, logo wall, contact) and `projectData.ts` (featured copy and project display rules); the site renders it unchanged. The agent profile adds the admin About bio (`site_settings.about_bio`) and shows résumé and calendar links when those admin fields are set. The `specializations` list in `profile.ts` is new copy drawn from claims the portfolio already makes; it also feeds the structured data. WillBot's background entries are not published.

Validation: 66 tests pass with `npm test` (Node 22.18 or later, which runs the TypeScript modules directly). They include new route, project-data, and generator tests (fixture pages, `noindex`, JSON-LD, `llms.txt`, sitemap, and inert HTML, `<script>`, `$`, and disguised `javascript:` links in CMS text), a real Vite build that must report its own errors rather than the plugin's, and `check:agents` runs against a local server that must fail when a page falls back to the homepage. The strict Node typecheck is clean; the app typecheck shows only its 19 existing errors; ESLint is clean on every touched file. Headless Chrome renders the same visible text as the pre-change build on nine views, and screenshots of the homepage, a case, and the career page match. Browser checks cover old hash links on load and inside the running app, back and forward between home, archive, cases, and career, lens and logo links, a project without a generated page, the admin login, and the agent copy being gone after mount with no console errors. Removing the `page-meta` block or making Supabase unreachable fails the build with a clear message.

Not verified: Vercel serving `/project/<id>` from `project/<id>/index.html` on a real deployment. That follows Vercel's documented routing (static files take precedence over rewrites; `/about` and `/about/` serve the same page) and is emulated in `vite preview`, but run `npm run check:agents -- https://dzierson.com` after the next deploy. The current production site already serves `.md` files as `text/markdown` and `.txt` as `text/plain`. Also unverified: the Vercel firewall's treatment of real AI crawlers, and how each AI product's fetcher reads the pages; the local checks used a GPTBot user agent. Canonical URLs use `https://dzierson.com` as the existing code does, but Vercel currently redirects the apex to `www` with a 307. Making `dzierson.com` the primary domain in Vercel would remove that mismatch.

Independent review: a fresh reviewer read the full diff, rebuilt against the live CMS, and repeated the browser checks. Verdict: with fixes, no critical issues. Two defects were fixed with tests that failed first. First, the plugin ran in `closeBundle`, which Rollup also calls after a failed build, so an unrelated build error surfaced as an agent-pages error; it now runs in `writeBundle`. Second, `check:agents` passed when a page fell back to the homepage; each page must now carry its own canonical path. Two owner decisions remain open: the canonical domain (above), and whether the redeploy step after hiding or unlisting a case is acceptable. Minor follow-ups: essay dates come from the CMS `created_at` field, `portfolio-route.ts` repeats the path patterns in `routes.ts`, `render.ts` builds `.md` links by hand, and plugin errors carry a doubled prefix.

Nothing is committed or deployed. The changes are on the local branch `agent-readable-site`, awaiting the owner's local review.
